# Phase 2 Testing Blueprint
**Prerequisite:** isolated fixtures — a disposable stack (`docker compose -p pos-test up`), two tenants × two restaurants, one user per role, a seeded `demo` tenant for the storefront. Install Go in CI.
Order: (1) **Security regression suite** (API-level, per route): unauthenticated, wrong-tenant, header-override, impersonation-header, role-matrix across all 363 routes → confirms/refutes clusters A–F and the in-handler-check inventory. (2) Payments: webhook forgery, replay, mock-vs-live mode. (3) Order/inventory/POS workflows incl. concurrency (order numbers, double submit, offline replay). (4) Accounting invariants (balanced entries, rounding, reversal, concurrent posting). (5) Subscription lifecycle/trial. (6) Contract tests for the 8 orphan + 1 mismatched dashboard calls and storefront `/public/*`. (7) Playwright per role: every authenticated route at 8 viewports × en/ar, console/network clean, axe accessibility. (8) KDS WebSocket auth/scope/reconnect. (9) Reliability: DB/Redis down, stub-mode behaviour. (10) Performance baselines on a production build. Run existing suites first (62 Go test files incl. 8 build-tagged; 59 frontend) and record results.
