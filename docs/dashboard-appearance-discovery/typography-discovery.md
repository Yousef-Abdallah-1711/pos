# Dashboard typography evidence

`frontend/apps/dashboard/src/app/[locale]/layout.tsx:2` imports Inter from `next/font/google`, configures the Latin subset at line 15, and applies its generated class to the locale wrapper at lines 54 and 60. `tailwind.config.js` extends colors but does not define an explicit font family or font-size scale; utility sizes and weights elsewhere therefore require inspection against the installed Tailwind configuration. The root page uses a wrapper, so inspecting only `body` is insufficient.

In the local synthetic-owner development browser on 2026-11-27, computed `font-family` on dashboard `main` and its `h1` was `Inter, "Inter Fallback"` in both EN and AR; on `html` and `body` it was the default system sans-serif stack. Computed CSS family does not establish the font actually used for every Arabic glyph or prove a downloaded font loaded successfully. Verify glyph fallback and licenses from the actual generated assets and font provider before shipping; this audit did not establish those facts.

The [raw typography inventory](typography-inventory.csv) lists 2,999 candidate source lines, including next/font, font family/size/weight, line height, letter spacing and common Tailwind text/leading/tracking utilities. These include repeated lines, may omit dynamically constructed classes, do not represent distinct font sizes, and are not classified or permission-reviewed. Review POS, KDS, dense tables, numbers, charts, dialogs, forms and mobile/RTL separately before a tenant-configurable font scale is implemented. The provisional registry names Manrope, Fraunces and IBM Plex Sans Arabic as proposed future choices; none is established as the current dashboard font or approved without operational readability and license verification.
