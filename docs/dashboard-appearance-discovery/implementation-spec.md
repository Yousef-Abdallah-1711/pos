# Future workspace appearance — implementation specification

Status: NOT STARTED. Platform Coral, tenant workspace settings, personal mode and public storefront branding have separate ownership. Build a versioned, allowlisted semantic token contract with the approved landing palette as fallback. Preserve semantic status and chart colors. Use Manrope for operational English body, IBM Plex Sans Arabic for Arabic, and reserve Fraunces for selected headings; verify operational density and contrast. Existing user colors and site themes require a documented migration and must not silently overwrite each other.

Recommended design to validate: tenant-owned, versioned JSON override plus revision and audit metadata in a tenant-scoped table, with forced RLS and transaction-local tenant context. Resolve built-in defaults followed by published tenant overrides, scoped authorized preview, and the user's mode preference. Restrict colors to validated values, fonts to a bundled allowlist, numeric typography to bounded ranges, and reject unknown keys and raw CSS. Enforce accessible combinations and use optimistic concurrency. The database is authoritative; client state is a cache. Determine existing RBAC permission ownership before implementing writes.

Add authenticated read and permission-protected write/reset operations using existing middleware and `database.WithTenantTx`, including audit in the same transaction. Validate cross-tenant denial and concurrent writes with real PostgreSQL integration tests. Provide explicit preview, save/publish, reset, unsaved changes and errors in a workspace appearance UI. Keep storefront theme APIs independent, remove or replace the existing implicit synchronization only after a compatibility strategy is verified. Apply tokens to shared shell, sidebar, portals, controls, tables, POS, KDS and other actual route consumers in phases. Existing financial and order behavior remains unchanged.

After application acceptance, seed disposable synthetic tenants and regenerate real EN/AR × light/dark screenshots and provenance. Update `CaptureMedia.tsx`, `captures.json`, screenshot matrix and all marketing usages; verify hero, bento, order story, showcase, full-capture links and image geometry. Test responsive, RTL, reduced motion, zoom, accessibility, browser engines, performance, tenant isolation, authorization, recovery, and production builds. Document physical-device and screen-reader gaps explicitly.

The accompanying token registry is a provisional starting point, not a complete reviewed design system. A mathematical sRGB contrast check of its proposed foreground/background, foreground/surface, secondary/background, primary foreground/primary, selected foreground/background, and sidebar foreground/background pairs found ratios of at least 5.72:1 in both modes. This does not validate other combinations, non-text states, charts, dynamic overrides or real rendering; implement and test those separately. Semantic status colors are provisionally fixed rather than unrestricted tenant branding controls.
