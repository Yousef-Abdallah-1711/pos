# Current application and appearance state

- `frontend/apps/dashboard`: Next.js 16 app router, locale root `src/app/[locale]/layout.tsx`, `next-themes`, Inter via `next/font/google`, `next-intl`, and `AuthProvider`. The operational shell is `src/components/layout/DashboardLayout.tsx` and navigation lives in `Sidebar.tsx`.
- POS and kitchen are dashboard routes under `src/app/[locale]/dashboard/{pos,kds}`; the shell treats their non-settings routes as fullscreen. `frontend/apps/restaurant-website` serves the independently branded storefront. `frontend/apps/super-admin` is a separate platform application. `frontend/apps/landing` owns marketing and platform entry forms. `frontend/packages/` contains shared workspaces including form foundation and i18n. Backend HTTP routes are wired in `backend/cmd/api/main.go`; persistence is in `backend/internal/repository` and `backend/migrations`.
- `src/app/globals.css` defines blue `--primary-50` through `--primary-900`, indigo secondary, green accent, and light/dark foreground/background defaults. `tailwind.config.js` maps primary/secondary/accent utilities to those variables. Numerous components instead use fixed Tailwind colors; see the raw inventory.
- `src/stores/preferencesStore.ts` persists personal settings and derives shade palettes by writing root CSS custom properties. `DashboardLayout.tsx` loads `/users/{id}/settings` and applies them. Root `next-themes` manages the light/dark/system class. Existing user data must not be assumed to be tenant workspace configuration.
- `src/app/[locale]/dashboard/settings/appearance/page.tsx` saves personal theme and color endpoints; `syncBrandColorsToActiveTheme` also updates the active website theme. This is a real existing coupling that the future work must address with explicit migration and compatibility tests.
- Existing `backend/internal/handler/http/admin_theme_handler_v2.go`, theme service/repository and theme migrations concern restaurant/site themes. User settings and related audit tables are defined by migrations `040_create_user_settings.sql` and `165_rls_user_settings.sql`; the latter enforces tenant scope via `users`. Database transactions use `backend/internal/pkg/database/tenant_tx.go`.

The inventories currently contain 79 dashboard `page.tsx` source files, 129 non-test TSX files under `src/components`, 12,305 raw color literal, function, utility and token matches, 2,999 typography-related lines, and 38 product-related image files (37 within `public/images/product`, one historical capture outside it). These are not counts of verified routes, distinct colors, shared components, or active screenshots. The color scan includes semantic, structural and repeated values; every classification requires review. The typography scan includes family, size, weight, leading and tracking candidates; it does not prove complete coverage or configurable behavior. Only the matrix manifest records capture metadata; other files require verification. Twenty-four authenticated synthetic screenshots, including one staff state without role assignments, are documented in [the baseline](baseline/README.md); they do not cover the entire application or other restricted roles.

The current color scanner found 609 occurrences containing a `blue-` utility among matches across 424 source files. This is a count of regex occurrences, not a count of confirmed legacy-branding defects: some blue usage may be informational, chart-related, disabled, test-only or otherwise intentional. The proposed migration must review semantics instead of replacing those matches wholesale.
