| Finding | Before | Fix | Evidence | Status |
|---|---|---|---|---|
| **SEC-A** impersonation header bypass (BE-001, SEC-001) | CONFIRMED at middleware (header skipped auth, placeholder user id 1) | `AuthMiddleware` accepts `X-Impersonation-Token` only through an `ImpersonationAuthenticator`. It validates the hashed token against `impersonation_sessions` (active, unexpired), loads the real target user, rejects super-admin targets and tenant mismatches, and sets impersonation context. Invalid, forged or expired tokens give 401 with no fallback to a bearer token. With no authenticator wired (DB down) the header is rejected. Files: `middleware/auth.go`, `impersonation.go`, `cmd/api/main.go` | 6 unit tests (`auth_impersonation_test.go`) + 3 smoke checks | **FIXED.** The valid-session path was verified with a fake authenticator. A real super-admin → impersonate → dashboard round trip was not exercised (needs a super-admin fixture, Phase 2B) |
| **SEC-B** client-controlled tenant (DB-001, SEC-026, BE-005) | STATIC (headers overrode JWT when `restaurant_id`=0; public routes trusted the pair) | `NewTenantContextMiddleware(verifier)`: tenant always from the JWT; X-Tenant-ID ignored for authenticated users; restaurant from the JWT, or from the header only if the SQL verifier confirms it belongs to the token's tenant; anonymous public routes need a verified consistent pair; no verifier gives 403 (fail closed); verifier error gives 503. Files: `middleware/tenant.go`, main.go | 9 unit tests + smoke (spoofed headers land in tenant A by DB check; mismatched public pair gives 403) | **FIXED** |
| **SEC-C** passwordless `/auth/login/confirm` (SEC-002, FE-OTH-001) | STATIC | `Login` issues a 5-minute signed selection proof (audience `pos-saas:login-selection`, covers email + tenant ids, random `jti`) only after bcrypt succeeds. `LoginConfirm` requires it, checks email/tenant coverage and burns the `jti` (single use) only after the selection is valid. Session tokens and selection tokens are not interchangeable. Landing login and both TenantSelectorModals pass `selection_token`. | 4 jwt + 7 usecase tests, 2 smoke checks | **FIXED.** Single-use store is per process; several replicas need a shared store (Phase 2C) |
| **SEC-D** decorative RBAC (BE-002, SEC-003) | PARTIALLY_CONFIRMED (middleware only stored values; some handlers self-check) | `NewPermissionMiddleware` compares the user's effective level (role_permissions across the user's roles + KDS/TABLES built-ins + legacy owner/admin claim) with the route's declared level. Modes: `enforce` (default in production, fails closed on lookup error) and `audit` (default elsewhere, logs would-deny, refused in production). Wired into `wrapWithPermission` and the KDS wrapper. **Also fixed a route→module mismatch:** 28 `/hr/*` routes were registered under module 2 (CATEGORIES). Now employees, roles, attendance → 3 (HR); leaves → 11; salaries → 12, per the seeded `modules` table. Otherwise a plain employee (READ on CATEGORIES) could read salaries under enforcement. | 6 unit tests + smoke: employee without grants gets 403 on salaries and product create, owner gets 200 (test stack runs `enforce`) | **PARTIAL.** Enforcement covers the 193 + 7 declared routes. Routes with no wrapper at all (categories, users CRUD, drivers, notifications, themes, contact-info, `/rbac/*` writes) are still ungated. `rbac-route-inventory.json` lists the declared routes only |
| **SEC-E** public order isolation (DB-002, SEC-006) | NOT_REPRODUCED (no fixtures) | The tenant/restaurant pair is now verified (SEC-B). An object-level proof (unguessable tracking token per order, or phone match) is **not** implemented. It needs a migration plus storefront and POS changes. | smoke: mismatched pair gives 403 | **OPEN.** Design: add `public_tracking_token`, return it on create, require it on lookup and cancel (Phase 2C) |
| **SEC-F** theme IDOR (DB-003) | STATIC | `loadOwnedTheme` / `themeBelongsToCaller` in `AdminThemeHandlerV2`: get, update, delete, activate and duplicate require tenant ownership and, for restaurant-scoped themes, restaurant ownership. Foreign and missing themes give an identical 404. The repository still filters by id only (defence in depth is a TODO). | 3 unit tests + smoke (5 cross-tenant attempts all 404, victim theme survives) | **FIXED at handler layer** |
| **SEC-G** Paymob mock default (SEC-004, BE-007) | STATIC (prod compose left mode empty) | `config.ResolvePaymobMode`: production requires explicit `live`. Empty or `mock` in production, unknown values, and live without API key / HMAC secret / iframe id make startup `log.Fatal`. Mock remains for non-production. `docker-compose.prod.yml` now requires `PAYMOB_MODE`, key, iframe and HMAC; `.env.prod.example` sets live. The live client's webhook verification code was not re-reviewed. | 6 config tests; test stack sets `mock` explicitly | **FIXED (configuration).** Webhook idempotency and replay (SEC-015) **OPEN** |
| **SEC-H** subscription enforcement (FE-OTH-031) | STATIC | The tenant status check now runs on every permission-wrapped route, the KDS routes and `wrapProtected`. Billing, `/me`, `/tenant/status` and `/rbac/me/*` use `wrapProtectedNoStatus`, so a blocked tenant can still pay and read its status. | 4 unit tests + smoke: disabled tenant gets 403 on a business route and 200 on `/tenant/status`, billing is not blocked, another tenant is unaffected | **FIXED for disabled tenants.** New tenants still get no `trial_*` dates (FE-OTH-003), so trial expiry never triggers — OPEN |
